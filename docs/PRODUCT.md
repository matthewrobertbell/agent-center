# Product and design principles

## Register

Product interface.

## Users

Professional software developers coordinating coding agents through an OpenCode server. They work in focused desktop sessions, switch between several active tasks, and need to recover recent context without losing space to navigation.

## Purpose

Provide a browser-based control surface for OpenCode sessions. A developer should be able to connect, scan and organize recent tasks, open a conversation, send work, and understand agent activity with very little interface overhead.

## Personality

Clean, professional, and space efficient. Calm and precise rather than playful. The interface should feel dependable enough to stay open all day.

## Avoid

- Generic administration dashboards
- Oversized cards or decorative metrics
- Excessive color
- Chat interfaces that waste horizontal or vertical space
- Terminal styling used only because the product serves developers

## Principles

1. Keep the current task primary and the surrounding chrome quiet.
2. Make dense navigation legible through grouping, rhythm, and strong selected states.
3. Prefer familiar desktop-product behavior over novel controls.
4. Reveal secondary actions when they become useful.
5. Communicate connection and agent state plainly, without visual noise.

## Accessibility

Target WCAG AA contrast, visible keyboard focus, semantic controls, full keyboard operation, and reduced-motion preferences. Never rely on color alone to communicate state.
